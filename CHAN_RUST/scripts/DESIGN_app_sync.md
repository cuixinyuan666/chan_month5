# 设计：把「双机同步」做进 App（设置里的一个按钮）

> 状态：**设计稿，未动代码**。等用户回复「确认」后再实施。
> 日期：2026-11-09
> 关联：`CHAN_RUST\scripts\sync_to_remote.ps1`、`remote_ctl.ps1`、`remote_app_agent.ps1`、`README_sync_remote.md`

## 一、目标

在 App 的**设置**里放一个「双机同步」入口：无论在 **PCA**（本机 `LAPTOP-NA22IFPU`，`192.168.1.5`）还是在 **PCB**（`192.168.1.6`，项目在 `D:\2\chan_month5`）上按下，都能把**当前这台的项目**推到**另一台的项目**，并做到：

1. 点一下就走完：探测 → 让路 → 推源码 → 推产物 → 校验指纹 → 把对端 App 拉回；
2. 覆盖前先看见「要覆盖什么」（差异清单 + 确认）；
3. 全程有进度与结论，失败能说清卡在哪一步，且能按快照回退。

## 二、已经是事实的底子（不用重做）

- 单向同步脚本 `sync_to_remote.ps1` 已在真机跑通：白名单（不镜像、不删对端自有数据）、产物指纹校验、遇占用自动让路、远端脚本补 BOM；
- 远端控制 `remote_ctl.ps1` + 常驻代理 `remote_app_agent.ps1`（1.2.0）已在 PCB 跑通：`ping / start / stop / status / command / screenshot / click / windows / report / reload / ps`，`start` 已会替用户点掉分笔太极；
- 判据口径：产物是否真同步看 `chan_kline.exe`(1028608) 与 `chan_ffi.dll`(1341440) 的 SHA256；API 是否起来看 `agent_live\agent_api_token.txt` 的修改时间。

## 三、前置条件（两条，必须先满足）

### 1. PCA 开一个专属共享

- 共享名 `chan_month5` → `D:\2\chan_month5`（2026-11-10 迁移后）
- 权限给 `Everyone` 读写（不走账号密码：PCA 是用户 `86185`、PCB 是 `Administrator`，跨机器走 `C$` 必然 401）
- 对端访问路径：`\\192.168.1.5\chan_month5`

### 2. 两边各跑一个同款代理

**这一条是本设计对早前判断的修正**：在 PCB 上点按钮时，挡路的是 **PCA 自己的 App**（它锁着自己的 `chan_kline.exe`/`chan_ffi.dll`），而 PCB 远程关不掉它——远端建进程这条路（`schtasks /S`、CIM、DCOM、合成按键）已实测全部不通。所以两边都需要「在自己机器上关自己 App」的能力。

- 做法：把现有 `remote_app_agent.ps1` 在 PCA 上同样启动一次（`-RepoRoot D:\2\chan_month5`），并加一个 Startup 入口；
- 复用现有 `启动远端代理.bat`（改一处 `RepoRoot`），不新增代码；
- 退化路径：**对端没代理也能推**——只要对端此刻没开 App（exe/dll 没被占用）就照常同步，只是不能自动关/拉。

## 四、交互设计

### 入口

设置面板里新增一栏「双机同步」，与「电报通知 / 机器学习」同级，展示一行状态：`上次同步：10:35 成功（PCA → PCB）`。

### 对话框（`showAppSyncDialog`）

| 区块 | 内容 |
| --- | --- |
| 对端路径 | 输入框，默认按主机名自动填：PCA 上填 `\\192.168.1.6\D$\2\chan_month5`；PCB 上填 `\\192.168.1.5\chan_month5` |
| 按钮 | 「测试连接」（只读：共享可达？对端代理在不在？exe/dll 是否被占用？）／「立即同步到对端」／「按快照回退」 |
| 差异预览 | 点同步后先出：`新增 N / 覆盖 M / 跳过 K`，可展开看前 30 个文件名；勾「本次不再询问」后直接走 |
| 进度 | 逐行追加：①探测共享 ②探测占用 ③关对端 App ④推源码 ⑤推产物 ⑥模板与 BOM ⑦指纹校验 ⑧重拉对端 App |
| 结论 | 成功：`已同步 N 个文件，指纹一致，对端 App 已拉起（pid=…）`；失败：具体原因 + 已写文件数 + 「回退」按钮 |
| 说明 | 按钮旁「?」弹出一段：这个按钮做什么、会覆盖什么、不会删什么、失败怎么办（项目规范：新增设置必须有说明弹窗） |

## 五、同步口径（与已定规则一致）

- **发起方为准**：覆盖对端同名文件；**绝不删除对端独有文件**（不做 `/MIR`）；
- **白名单复用**现有排除清单（`.git`、`build`、`target`、`a_Data\robot_verify`、`a_Data\remote_ctl`、日志与临时文件等），不新增第二套口径；
- **快照**：只把「即将被覆盖的文件」在**对端**存到 `a_Data\remote_ctl\sync_backup\<时间戳>\`，保留最近 3 份；任何一步失败立刻停，不继续后续层；
- **占用处理**：对端 exe/dll 被占用 → 调对端代理 `stop`（只关它自己拉起的那个，手开的不碰）→ 推完若原来在跑 → `start`（自动点掉太极）→ 返回截图与 pid。

## 六、技术实现

### 组件

```
lib/settings/sync_settings_store.dart      新增：对端路径、上次同步时间/结果（落盘 .chan_sync_settings.json）
lib/sync/app_sync_service.dart             新增：探测/差异/同步/回退的编排，调 PowerShell 脚本并流式回吐输出
lib/sync/app_sync_dialog.dart              新增：上述对话框
lib/main.dart                              改：设置面板加入口 + 状态行
CHAN_RUST/scripts/sync_to_remote.ps1       改：加 -DiffOnly / -Backup / -Json / -PeerCtl（对端代理路径）
CHAN_RUST/scripts/README_sync_remote.md    改：补 App 内入口与参数
```

**为什么 App 调脚本而不是在 Dart 里重写**：白名单、让路、BOM、指纹校验这些口径已经在脚本里跑通过；App 只做参数与展示，避免两套实现漂移。App 已有起外部进程的能力（导出功能在用）。

### 调用链（以 PCA 点按钮为例）

1. App 算仓库根：`CHAN_DATA_ROOT` 的父目录（或 `RobotVerifyPaths.resolveRepoRoot()`）；
2. `sync_to_remote.ps1 -SharePath <对端> -DiffOnly -Json` → 差异清单；
3. 用户确认 → `sync_to_remote.ps1 -SharePath <对端> -Apply -Backup -Json -RestartRemoteApp`；
4. 脚本内部按需 `remote_ctl.ps1 -SharePath <对端> -Action stop|start`；
5. App 逐行读 stdout（脚本加 `-Json` 时输出结构化事件行），渲染进度与结论；
6. 成功/失败写回 `.chan_sync_settings.json`。

### 主机身份判断

```dart
// 伪代码：谁按下无所谓，目标是"另一台"
peerDefault(hostname) => hostname == 'LAPTOP-NA22IFPU' ? r'\\192.168.1.6\D$\2\chan_month5' : r'\\192.168.1.5\chan_month5';
```

## 七、失败口径

| 情形 | 表现 |
| --- | --- |
| 共享不可达 | 立刻报「对端共享不可达」，不动任何文件 |
| 对端 App 占用且无代理 | 报「对端 App 正在运行且那边没有代理，请在 PCB 上关掉 App 再试或装代理」，不动任何文件 |
| 对端代理未响应 | 超时后如实报「代理未响应」，不假装成功 |
| 推到一半失败 | 停在该步，列出已写文件数，提供「按快照回退」 |
| 指纹不一致 | 报具体哪个文件不一致，并把新值/旧值都列出来 |

## 九、已知限制（先说清，不藏）

1. **`.git` 不同步**：两边提交历史各自独立，代码改动过去但历史不过去；要共享历史只能走远端仓库（已明确不走 git 当同步通道）。
2. **`a_Data\robot_verify` 只同步模板**：对端的验证现场与报告不会被覆盖（这是为了不再犯 11-02 那次覆盖事故）。
3. **`task-log.md` 以发起方为准**：在那台上改了 `task-log` 会被覆盖回来。
4. **代理必须在已登录桌面会话**（session ≠ 0）里跑，否则关/拉 GUI 无效。
5. **快照只覆盖「被覆盖的文件」**，不是全盘备份；`build` 目录被整体替换时，旧产物不在快照里（可由 `git`/重编恢复）。

## 十、不做的事

- 不做双向自动合并（没有按内容合并的规则，只有发起方覆盖）；
- 不做后台定时/监视自动同步（同步必须是显式按钮，用户原话「我发指令才同步」）；
- 不改 `AGENTS.md`；
- 不改任何缠论计算逻辑（本设计只涉及 UI、脚本与配置）。
