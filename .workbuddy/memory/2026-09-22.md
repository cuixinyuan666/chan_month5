## Bug 修复：一次性走完的太极窗口导致进程退出（Win32 FFI 回调失效）

- 现象：`flutter run -d windows` 运行期直接 Crash，`runtime_entry.cc:5143 error: Callback invoked after it has been deleted`，isolate=`yin-yang-overlay`，堆栈落在 `startWindow → CreateWindowEx`。
- **根因（重要，可复用教训）**：`Pointer.fromFunction` 注册的 WndProc 只是 FFI trampoline，**isolate 结束即失效**；但 `RegisterClass` 注册的窗口类活到进程结束，其 `lpfnWndProc` 永久指向第一次注册的那个 isolate。旧代码每次 show/hide 都 spawn/kill overlay isolate（`Isolate.kill(beforeNextEvent)` 还会抢跑，留下「窗口还在、回调已废」的孤儿），第二次 CreateWindowEx 在建窗过程中回调失效指针 → VM 直接 abort 整个进程。
- 改动文件（3 个，非缠论内核）：
  - `widgets/yin_yang_overlay_isolate.dart`：isolate 常驻、窗口复用；hide=SW_HIDE 不拆窗；stop 严格按「停表→DestroyWindow→UnregisterClass→isolate 退出」；类名带时间戳 + RegisterClass 失败先注销再注册。
  - `widgets/yin_yang_native_overlay.dart`：新增懒 spawn 复用（`_ensureIsolate`）与 `dispose()`；彻底去掉 `Isolate.kill`。
  - `main.dart`：`dispose` 里 `hide()` → `dispose()`。
- 验证：`flutter analyze`（3 文件）无新增告警；`flutter build windows --debug` 30 秒内通过（「Built build\windows\x64\runner\Debug\chan_kline.exe」）。GUI 验收：连续两次/三次长按「一次性走完」，进程不再退出。
- **通用结论**：凡「Dart isolate + Win32 窗口过程」写法，WndProc 要么放 native 侧，要么保证 isolate 与窗口同生命周期。

## 口径共识：K{n}回归通道（grill-me 追问后定稿，待用户「确认」后实施）

用户否决了 09-22 凌晨那版「固定 N 根滑窗收盘价回归」，真实口径是通达信/金字塔「回归通道」画线工具的逻辑，只是**区间端点用缠论点位**替代手选：

- 基准区间：父层 K{n+1} 连线在 asOf 视图下的**最后一段**（倒数第二个极点 → 最后一个极点），端点含「分型判断 / 构建中开口」端点；**只取最后一段，不往回追到整条连线首尾**（走出多段后才分岔，用户选 A）。
- 样本钟：K0 用区间内每根 K0 收盘；K1+ 用右端 x 落在区间内的本层虚拟K收盘（与布林同钟）。
- 回归：最小二乘等间距 → 中轨；上下轨 = 中轨 ± k × **残差总体标准差（除 N，项目布林口径）**；k 默认 2.0，可调；**删掉「回归通道 N」设置项**。
- 绘制：中轨实线、上下轨虚线、不填充；从区间起点一路**外推到 asOf 截断**（平行通道，宽度常数）。
- 回看：十字 asOf 回退时基准连线取**当时可见**的最后一段（不泄漏未来）。
- 不可用：父层还没形成连线、或区间内样本 < 2 → 该层不画。
- 不回写冻结仓/会话历史；父层端点一变，通道起止跟着变（用户明确接受历史外观跟着当前步微调，与「冻结不回写」的常规口径是刻意的例外）。
